# Windows 人工验收表

验收记录应填写实际机器、Windows 构建、安装包 SHA-256、开始/结束时间及通过/失败证据；未执行一律写“待验证”。不要用单元测试代替扫码成功。

## A. 干净电脑

1. 使用全新的 Windows 11 x64 标准用户虚拟机；另准备 Windows 10 22H2 x64。确认没有 Node、npm、Python、Docker、.NET Runtime。保留系统安全功能。
2. 分别下载已核对来源的 `BigFishSetup-CN.exe` / `BigFishSetup-Global.exe`；核对 SHA-256。双击，不应要求提升管理员权限。也单独验证直接运行版 `BigFish-CN.exe` / `BigFish-Global.exe`。
3. 点击检查环境，看到 Node/npm/DSH 待安装；Windows、目录与网络结果应来自真实检查。
4. 默认不选 B站，点击一键安装。确认没有终端窗口闪烁；UI 可拖动和取消。
5. 核对私有 Node 目录内有官方 LICENSE；日志包含真实版本及 npm 执行结果。系统 PATH、全局 npm、用户 `.dsh` 未被修改。
6. 确认 DSH CLI、HTTP 认证、IM RPC 均通过，浏览器能打开。管理服务只监听 127.0.0.1；其他设备不能访问。
7. 确认没有下载 Python 或 Whisper。关闭 BigFish 后 Node 服务退出，再次打开、启动正常。
8. 在工作区放文件，在 DSH 建会话并保存模型设置。重启电脑，再运行、修复、重复安装两次；文件、会话和模型设置保持原样，健康依赖不重复安装。

## B. 已有环境与异常

| 条件 | 预期 |
| --- | --- |
| 系统 Node 18 或损坏 npm | 安装私有 Node 24；旧安装不卸载 |
| 系统 Node 24.9+、npm 正常 | 真实执行后复用 |
| Node 只在 Program Files、PATH 无记录 | 从常见目录发现并执行 |
| npm.ps1 被策略拦截 | 通过 node/npm-cli.js 正常运行，不修改策略 |
| 用户/安装/工作区含中文、空格、`&` | 所有命令参数保持原值 |
| npm 网络中断或断网 | 有界重试/超时，明确失败；重试后恢复 |
| Node ZIP 被篡改 | SHA-256 失败，不能执行 |
| 3080 被普通网页服务器占用 | 不关闭该服务器；使用其他实际端口 |
| 3080 为独立 DSH | 不接管没有认证/目录归属证明的实例；提示并隔离启动 |
| 原有 `~/.dsh` 与会话 | 发现并保留，不自动迁移/重写 |
| 同一数据目录打开第二个 BigFish | 阻止并发修改，不杀另一实例 |
| 安装目录无写权限 | 清楚显示错误；在高级选项选可写目录后继续 |
| 安装期间取消/关闭窗口 | 停止后续步骤，终止自己拥有的进程树；重新运行可恢复 |
| DSH 无启动 URL/服务退出 | 不显示成功；输出脱敏的具体诊断 |
| 系统重启、安装器异常终止 | 不遗留 Job 对象拥有的服务；下次依状态重检 |

## C. 模型与 QQ

1. 在 DSH 设置 → 模型 中输入用户自己的 API Key。手动测试短消息。分别测试无效密钥、无余额或限流的错误说明。不要把密钥截图放进公开验收报告。
2. 设置 → IM机器人 → QQ，验证上游官方机器人创建与扫码流程。另用已有机器人凭据绑定一次；不输入个人 QQ 密码。
3. 在插件页面和 BigFish 的测试连接中确认真实状态变化。向机器人私聊发送短消息，观察回复和对应 DSH 会话。
4. 仅在机器人实际获准的群中测试群聊。记录腾讯授予的权限与应用状态；不能因为私聊可用就声称所有群可用。
5. 取消扫码、二维码失效、网络断开再恢复，界面应显示真实状态，不伪造连接成功。

## D. 微信

1. 用获得相关能力的测试账号进入微信绑定页面，扫码并在手机确认。
2. 检查真实连接状态和短消息往返；重启 DSH 后检查持久绑定。
3. 用未获权限的账号检查失败提示。不能将此情况描述为安装器已绕过权限或全部微信账号可用。
4. 不测试逆向协议、不索取账号密码、不尝试越权群发。

## E. 可选 Bilibili

1. 在空白基础安装上勾选 B站。确认只在这次操作才下载 uv/Python，环境位于私有目录。
2. 核对 HTTP status 与 Python import 检查都成功；不要仅看 `.venv` 文件存在。
3. 确认首次 `autoComment=false`、`replyToComments=false`、`dmMode=off`、`peakValley=false`、`transcribe=false`。
4. 在设置 → 刷B站 扫码，手动点击“现在跑一轮”，确认报告产生，未发送评论/回复/私信。
5. 测试可选依赖下载失败，基础 DSH 与 IM 仍可启动。旧用户自定义设置不能被重新安装清空。

## 发布门槛

必须通过 A–D 才能宣称基础版在干净 Windows 上一键部署通过验收。E 未通过时把 B站标为实验性。未签名发布说明 SmartScreen 状态；正式签名由维护者证书完成，不自动修改 Defender 白名单。

自动化入口：`scripts/windows-acceptance.ps1`；该脚本使用私有 Node 强制覆盖“未预装 Node”的路径，执行实际安装与重复安装，但 GitHub runner 本身并非完全空白系统。完整的“无任何 .NET Runtime”结论仍需 A 的干净虚拟机。

## F. 中国源 / 国际源

分别用 `scripts/windows-acceptance.ps1 -Region cn` 和 `-Region global` 验收；两版首次语言均为中文。高级选项切换源后重启，确认设置保留。测试镜像 404/网络失败可有限回退官方，integrity 错误不可回退。已有英文 locale 不应被覆盖。
